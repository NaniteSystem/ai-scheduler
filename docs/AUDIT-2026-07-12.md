# Фундаментальный аудит Nebulla — 2026-07-12

Полный проход по всем модулям «свежим взглядом»: данные → store → движки → AI-слой → каждый экран и каждая кнопка. Базовое состояние: `tsc` чисто, 5/5 тестов зелёные, i18n-паритет 957×3 ключей.

Формат: **[критичность] находка → почему это проблема → что делать**.

---

## A. Сломанное поведение (баги)

### A1. [CRIT] Свайп по карточке задачи не работает нигде
`GTDView.tsx:130`: `swipeEnabled = … && !(matchMedia('(pointer: coarse)').matches)` — свайп **выключен на тач-устройствах**, а на десктопе touch-события не приходят вовсе. Итог: фича мертва целиком, при этом мобильная подсказка «свайпни задачу» (`gtd.swipeHint`, показывается `md:hidden`) обещает то, чего нет.
→ Вернуть свайп на тач (условие инвертировано либо оставлено от конфликта со скроллом — решить конфликт осями, как уже сделано в triage-круге), либо убрать и свайп-код, и подсказку.

### A2. [HIGH] «Missed» показывает сегодняшние сессии как пропущенные (таймзона)
`ScheduleView.tsx:619`: `isPast(new Date(s.date))` — `new Date('yyyy-MM-dd')` парсится как UTC-полночь; в UTC+3 сегодняшняя дата «прошла» уже в 03:00. Плюс заголовок `Missed` захардкожен по-английски.
→ Сравнивать date-строки (`s.date < todayStr`), ключ i18n.

### A3. [HIGH] Частичный прогресс счётчиковой привычки = «failed»
`store.incHabit`: пока `count < targetCount`, пишется `status:'failed'` → название краснеет (Home и HabitsView красят failed красным), heatmap рисует красную клетку, `habitRate`/streak считают день провалом. 3/8 стаканов воды — не провал.
→ Ввести честный статус `partial` (или писать count без status) и не красить красным.

### A4. [HIGH] Снятие галочки привычки ставит «rest», а не очищает
Home `renderHabitRow` и HabitsView: повторный тап по «выполнено» → `setHabitStatus(…, 'rest')` («оправданный пропуск»). Случайный двойной тап тихо записывает день как rest, очистки нет (clearHabitDay есть только у счётчиков).
→ Повторный тап = `clearHabitDay`. Rest — только явной кнопкой-луной.

### A5. [HIGH] Анкор привычки исчез из редактора
`HabitModal`: `const anchor = habit?.anchor || 'none'` — UI выбора «когда» (после пробуждения/обеда/…) удалён. Все новые привычки падают в группу «none», группировка Today-списка по времени дня и время в AI-планировщике деградируют. Поле стало зомби.
→ Вернуть чипы anchor (они были) либо осознанно выпилить anchor из модели и группировать по reminderTime.

### A6. [MED] Напоминание привычки: показывает 09:00, когда не задано, и не очищается
`HabitModal`: TimePicker получает `hmToMin(reminderTime || '09:00')` — выглядит установленным; одно касание реально устанавливает; кнопки «убрать напоминание» нет (раньше была).
→ Явное состояние «нет напоминания» + кнопка ✕.

### A7. [MED] deleteSeries оставляет задачи-сироты
`store.deleteSeries` удаляет сессии, но зеркальные GTD-задачи (`sessionId`) остаются в Scheduled с висячими ссылками (deleteSession — корректно трэшит).
→ Симметрично трэшить/чистить зеркала серии.

### A8. [MED] Manual-цель: категория всегда «personal»
`GoalCreateWizard.createManual`: `const cat: Category = 'personal'` — выбор категории (был по споекам) потерян, все ручные цели 🧠-фиолетовые.
→ Вернуть шаг выбора категории (сетка эмодзи-чипов).

### A9. [MED] Drag-reorder задач — плацебо
`reorderTasks` переставляет массив и пишет несуществующее в типе `_order`, но список всегда пересортируется по priority/due/created → перетаскивание визуально работает, результат мгновенно затирается. Заодно обновляет `updatedAt` у ВСЕХ задач (ломает stale-детектор weekly review).
→ Либо режим «ручная сортировка» (sortBy:'manual', честный order), либо убрать drag полностью.

## B. Продуктовые дыры (непродуманная логика)

### B1. [CRIT] Зеркалирование «сессия ↔ GTD-задача» замусоривает задачи
Каждая сессия с датой автоматически рождает GTD-задачу в Scheduled (`taskFromSession` + `syncScheduledSessions` в App-эффекте). Коммит плана AI-планировщика на 2–4 недели создаёт сессии для **еды, спорта, отдыха, привычек** (sourceKind life/habit) → на каждую вырастает «задача» «Завтрак», «Отдых»… в GTD. Смысл списка задач разрушается.
→ Зеркалить только пользовательские задачи (sourceKind 'task' / ручные), life/habit-сессии не зеркалить. Провести миграцию-чистку существующих зеркал.

### B2. [HIGH] У AI-цели невозможно задать срок/темп/оценку часов
Wizard создаёт цель с `totalHoursEstimated:0, hoursPerWeekTarget:3`, дедлайна нет; редактор цели — только Rename. При этом весь блок «Pace» (нужно N ч/нед, weeks left), прогресс по часам, «Est.» на карточках — считаются от этих пустышек и показывают чушь/нули.
→ Добавить в детали цели редактирование: deadline, часы/нед, оценка часов (и шаг в wizard — опционально). Либо скрывать пейс-блоки, пока не заданы.

### B3. [HIGH] Recurring-сессии молча заканчиваются через 8 недель
`expandRecurrence(weeksAhead=8)` материализует ряд и всё. Серию нельзя отредактировать целиком (только удалить всю/одну).
→ Автопродление хвоста серии (при загрузке достраивать до горизонта) + «изменить всю серию» в редакторе.

### B4. [HIGH] Нет резервной копии данных
Всё живёт в localStorage/APK WebView. Экспорта нет; `restoreBackup` в store мёртв (ни одной кнопки). Потеря данных = потеря всего.
→ Кнопки «Экспорт JSON» / «Импорт JSON» в Settings → Data (restoreBackup уже готов), плюс починить приём `theme:'system'`.

### B5. [MED] Два конкурирующих планировщика, один из них — фейковый ИИ
Legacy «AI Day Architect» (475 строк): rule-based генератор дня с искусственной задержкой 1400 мс, шагами «анализирую…» и бейджем AI. Доступен только по ссылке «настройки →» из AIPlanner. Новый AIPlanner — настоящий гибрид.
→ Слить: Prefs-часть архитектора (ритм, работа, занятия, life-баланс) станет вкладкой «Preferences» в AIPlanner; однодневный фейковый генератор удалить (день покрывается горизонтом 1w) или честно назвать «быстрый план дня» без AI-маскировки.

### B6. [MED] GTD-статусы project / waiting-for / reference полумёртвые
Их нельзя выбрать в редакторе (маппятся в someday-maybe), `delegateTo` недостижим (виден только при waiting-for), «Projects overview» рендерится только при фильтре `project`, в который невозможно попасть из UI (нет таба; только из шага weekly review). Типы, конфиги, i18n-ключи — всё живёт.
→ Решение: либо честно упростить (оставить inbox/next/scheduled/someday/done, выпилить остальное), либо вернуть статусы в редактор + таб. Рекомендую упростить — приложение уже выбрало «лайт-GTD».

### B7. [MED] Open-end сессии искажают статистику
Номинальные 60 мин считаются в бюджете недели/дня, донате «время по задачам», часах цели.
→ Учитывать open-end planned как 0 в бюджетах (или отдельной строкой «без длительности»); в done — по факту (таймер уже пишет elapsed).

### B8. [MED] Быстрый захват: каждая задача получает «5m»
`captureTask(dur=5)` + `qd=5` → все захваченные задачи имеют chip 5m и планируются 5-минутками. Дефолт должен быть «не указано».
→ durationMinutes: undefined по умолчанию; заодно убрать дублирование capture-логики (App.capture и QuickCaptureBar повторяют один и тот же двухшаговый хак create→update — вынести в store.captureParsed()).

### B9. [MED] Прогресс-хаб: рудименты демо-эпохи
Плитки «Language h / Pages / Km» опираются на `progressLog.value`, который вводится только через редкий Log-drawer; «Session rate» подписан как общий, а считает все сессии за всё время. `EnergyChart` — название-рудимент.
→ Заменить на честные метрики (часы за неделю, выполнение по дням, серия), убрать категория-специфичные km/pages.

### B10. [LOW] Мелкие несостыковки модели
- `resetAll` не сбрасывает schedulePrefs/userProfile/generatedPlan/focusTimer/notifPrefs.
- Корзина никогда не очищается (нет «удалить навсегда» / автоочистки 30 дней).
- `deleteGoal` не отвязывает `habit.goalId`.
- weekly-привычка привязана к дню недели `createdAt` — день нельзя выбрать.
- `Goal.priority` влияет на планировщики, но UI выбора приоритета цели нет (у всех 2).
- Поля-зомби в типах: `Goal.sessionsCompleted/sessionsTotal/hoursLogged/nextSessionTitle/nextSessionDate`, `SessionType 'catchup'`, `GTDTask.completedPomodoros` (пишется, нигде не показывается).

## C. Переосмысление кнопок (по экранам)

- **Home**: у сессии два «выполнить» (кружок в строке + кнопка справа) — оставить один; тап по строке открывает drawer — ок. Кнопка-аватар = Settings (неочевидно, но приемлемо). Стрелка «→» у Scheduled ведёт в календарь — ок.
- **GTD карточка**: кнопка «Do» (Play) видна у всех кроме inbox/done — хорошо; «солнышко» Today-focus дублируется в bulk и More — ок; в More «Перенести на завтра» затирает dueDate без undo — приемлемо. Свайп — см. A1.
- **Триаж-круг**: 5 мишеней, «Inbox» внизу означает «оставить в инбоксе» но помечает processedAt → задача исчезает из триажа навсегда и остаётся в статусе inbox, при этом попадает только в счётчик inbox в lists-режиме… полусмысл. → Переименовать мишень в «Later»/«оставить» и определить судьбу (напр. в конец очереди).
- **Таймер (плашка)**: у незалинкованного таймера «✓ Done» и «✕» делают одно и то же (discard) — ✓ должен, как минимум, останавливать с сохранением факта (или прятаться).
- **Session drawer**: «Focus» + «Edit» + «Delete» + «Done» — ок; для series-сессии удаление предлагает только «всю серию» (нет «только эту») → добавить выбор.
- **Architect**: вся правая вкладка «Schedule» — фейковый AI (см. B5). Слайдеры life-баланса: выключенный блок красится `#080808` (чёрный в светлой теме), подпись «h/day» и бейдж «AI» не переведены.
- **AIPlanner**: время в превью 12-часовое AM/PM для всех языков; «Free day» — ок; кнопка «настройки →» уводит в другой экран со своим генератором — путает (B5).
- **HabitsView**: три кнопки статуса (✓/луна/✕) у обычной привычки — норм, но семантика повторного тапа сломана (A4); в Stats ретро-тап по клетке — ок.
- **Календарь**: «Новая сессия» в year-режиме превращается в «Новая цель» — неожиданно, но осмысленно; подсказка «дважды кликните» показывается и на таче, где работает одиночный тап → текст должен зависеть от устройства.
- **Onboarding/IntroCourse/Search/Archive/Settings** — консистентны; в Archive «Restore» у trash-задачи возвращает в Inbox (ок), но нет «удалить навсегда» (B10).
